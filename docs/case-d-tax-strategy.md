# 案 D: OCR 価格表示方針 — 個別=レシート記載通り / 合計=税込

> **採用日**: 2026-05-10
> **背景**: PR #26 (案 B: Gemini に税込換算 + 軽減税率自動判定を任せる) を実装したが、※マーク無しレシートで 8% 判定漏れが多発。Revert (PR #27) のうえで本方針へ切替。

---

## 1. 方針概要

| 項目 | 値 |
|---|---|
| 各品目 (`expense_items.total_price`) | **レシート記載のまま** (税抜表示なら税抜、税込表示なら税込) |
| 合計金額 (`expense_records.total_amount`) | **税込の最終支払額** (レシート末尾「合計」「お支払い」直前の金額) |
| 税率判定 (8% / 10%) | **しない** (Gemini に依頼しない) |
| 値引き処理 | レシート末尾の支払額に既に反映されている (Gemini はそのまま採用) |
| クーポン情報 | 既存通り `discounts` 配列に取得 → `note` フィールドに転記 |

## 2. 採用理由

### 2.1 案 B (税込換算 + 税率判定) の実害
- ※マーク無しレシートで Gemini が判定不能 → 全部 10% にフォールバック
- 食品なのに 10% で記録される事象が多発
- プロンプトを 3 段階判定に拡張する案も検討したが、Gemini の精度依存で根本解決にならない

### 2.2 案 D の利点
- **税率判定の不確実性を完全に排除** (そもそも判定しない)
- プロンプトがシンプル → OCR 全体の安定性向上
- 割引処理も「合計が支払額」だけ守れば自然に整合
- 既存 DB スキーマ変更なし
- レシート自体が「品目=税抜・合計=税込」表示形式なので、ユーザー体感も自然

### 2.3 トレードオフ (許容)
- 品目合計と全体合計の不一致 → 詳細画面に注釈で明示
- カテゴリ別円グラフは **税抜ベース** になり、ホーム合計と微妙にズレる (割合は変わらないので実害小)

## 3. ユーザーへの見え方 (例)

外税レシート + クーポン値引きの例:
```
食パン      ¥150
シャンプー  ¥500
─────────────
8% 消費税   ¥12
10% 消費税  ¥50
クーポン   -¥50
合計       ¥662
```

ReceiptLink での記録:
- 品目1: 食パン ¥150 / 食費
- 品目2: シャンプー ¥500 / 日用品
- **合計**: **¥662** (= 実支払額)
- メモ: `値引き: クーポン -50`

詳細画面注釈: **「※ 各品目はレシート記載通り (税抜・税込はレシート表示に依存)。合計は税込支払額です」**

## 4. 実装変更点 (本 PR)

| ファイル | 変更 |
|---|---|
| `supabase/functions/_shared/prompts.ts` | 「各品目はレシート記載のまま、換算しない」「合計は税込最終支払額」を明示 |
