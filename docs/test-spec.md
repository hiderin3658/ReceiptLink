## 2. テスト実行順序

データ依存があるため以下の順序で実施:

1. 認証・アクセス制御（**Section 4**） → ユーザー操作で Google ログイン
2. 設定 / プロフィール（**Section 9**）
3. 設定 / カテゴリ管理（**Section 10**）— 独自カテゴリ追加でデータ準備
4. 支出登録 / 手入力（**Section 5**）— 履歴データを蓄積
5. 履歴・詳細・編集・削除（**Section 6**）
6. ダッシュボード（**Section 7**）— 集計確認
7. レポート（**Section 8**）— 月次推移・前月比
8. 設定 / 固定費管理（**Section 11**）— 固定費登録
9. 固定費自動計上（**Section 7-c**）— ダッシュボードから一括計上
10. CSV エクスポート（**Section 12**）
11. ホワイトリスト管理（**Section 13**）— admin only
12. 支出登録 / レシート OCR（**Section 5-c**）— Edge Function 必要、最後でも可

## 4. 認証 / アクセス制御

### TC-AUTH-01 ⚠ 未認証で `/` にアクセス → `/login` リダイレクト
- **前提**: ブラウザのセッションをクリア（Chrome 拡張側のログアウトが必要）
- **手順**:
  1. `/` に navigate
  2. URL を確認
- **期待**: `/login` にリダイレクトされる
- **備考**: ログイン状態を保ったままだと検証不可。**ユーザー側で Chrome の Google アカウントからサインアウト**が必要

### TC-AUTH-02 ⚠ Google ログイン → ホワイトリスト通過 → `/dashboard`
- **前提**: 未ログイン状態、`hiderinchan3658@gmail.com` がホワイトリストに登録済み
- **手順**:
  1. `/login` に navigate
  2. 「Google でログイン」ボタンクリック
  3. **ユーザー操作**: Google アカウント選択
- **期待**: コールバック後 `/dashboard` に遷移、ダッシュボード表示

### TC-AUTH-03 ⚠ ホワイトリスト未登録 email でログイン → 拒否
- **前提**: ホワイトリストに無い別の Google アカウント
- **手順**:
  1. `/login` で別アカウントを選択してログイン試行
- **期待**: `/login?error=not_allowed` にリダイレクト、「このメールアドレスは利用許可されていません」エラー表示
- **備考**: 別アカウントが無ければスキップ可

### TC-AUTH-04 認証済み状態で各保護ルートに直接アクセス
- **手順**: `/dashboard`, `/expense`, `/expense/new`, `/reports`, `/settings` にそれぞれ navigate
- **期待**: 全て表示成功（401/403 にならない）

## 5. 支出登録

### 5-a 手入力

#### TC-INPUT-MAN-01 最小入力で支出 1 件登録（1 品目）
- **手順**:
  1. `/expense/new` に navigate
  2. 購入日: 今日（自動入力）
  3. 店舗名: 「テスト店舗A」
  4. 品目 1 行目: 品名「テスト品目A」/ カテゴリ「食費」/ 金額「500」
  5. 「登録する」クリック
- **期待**:
  - `/expense/{id}` にリダイレクト
  - 詳細表示でストア名「テスト店舗A」、合計 ¥500、カテゴリ「食費」が見える

#### TC-INPUT-MAN-02 複数品目（3 行）+ 合計自動計算
- **手順**:
  1. `/expense/new` で 3 品目（食費 ¥800 / 日用品 ¥350 / 食費 ¥120 値引 20）入力
  2. 合計金額欄を 0 のまま
- **期待**: 合計自動計算 = 800 + 350 + 120 - 20 = 1,250 円

#### TC-INPUT-MAN-03 必須項目バリデーション（品名 0 文字）
- **手順**: 品名を空白のまま「登録する」
- **期待**: 「品名は必須です」エラー、保存されない

#### TC-INPUT-MAN-04 値引額が金額より大きい / 負数入力
- **手順**: 金額 100 / 値引 200 で登録
- **期待**: zod バリデーション通過（個別の品目で値引 > 金額の制約は無いため通る）。合計はマイナスにならず 0 表示

### 5-b 固定費（recurring）由来の自動計上テストは Section 11 + Section 7-c

### 5-c レシート OCR ⚠

#### TC-INPUT-OCR-01 ⚠ モックレシート画像で OCR → フォーム自動入力
- **前提**: Edge Function `extract-receipt` がデプロイ済み、`GEMINI_API_KEY` 設定済み
- **手順**:
  1. `/expense/new` に navigate
  2. **ユーザー操作**: 画像選択ダイアログで `web/scripts/mock-receipts/output/*.png` を 1 件選択
  3. 「品目を抽出」クリック
  4. OCR 完了を待つ（10〜20 秒）
- **期待**:
  - 「✅ レシートを読み取りました」表示
  - フォームに店舗名 / 購入日 / 品目数件が自動入力される
  - カテゴリは AI 推定（外れていれば「その他」フォールバック）
- **失敗時のスキップ条件**: Edge Function 未デプロイの場合はテスト全体スキップ

#### TC-INPUT-OCR-02 ⚠ OCR 結果を編集して保存
- **前提**: TC-INPUT-OCR-01 完了
- **手順**:
  1. OCR 結果のフォームで品名 1 件を修正、カテゴリを 1 件変更
  2. 「登録する」クリック
- **期待**: 修正値が保存され、詳細画面で確認できる

## 6. 履歴・詳細・編集・削除

### TC-LIST-01 履歴一覧表示
- **前提**: 支出 1 件以上登録済み
- **手順**: `/expense` に navigate
- **期待**:
  - 月別合計セクションで該当月の合計が表示
  - 「最近の支出」に登録した記録がカード形式で表示
  - source_type に応じたアイコン（レシート/手入力/固定費）

### TC-DETAIL-01 詳細表示
- **手順**: `/expense` から記録カードをクリック
- **期待**:
  - `/expense/{id}` に遷移
  - 店舗名 / 日付 / 合計金額 / ソース（手入力 等）が表示
  - 明細リストにすべての品目とカテゴリ名（id ではなく名前）が表示

### TC-EDIT-01 編集して保存
- **手順**:
  1. 詳細画面 → 「編集」クリック
  2. `/expense/{id}/edit` で店舗名と品名を変更
  3. 「更新する」クリック
- **期待**: 詳細画面に戻り、変更が反映

### TC-EDIT-02 明細を 1 行追加して更新
- **手順**: 編集画面で「行を追加」→ 1 品目入力 → 更新
- **期待**: 明細件数が増え、合計も自動再計算

### TC-DELETE-01 削除
- **手順**:
  1. 詳細画面で「削除」クリック
  2. 確認ダイアログで「OK」（**ブラウザ自動操作で alert を accept する必要あり**）
- **期待**: `/expense` に戻り、削除した記録が一覧から消える

## 7. ダッシュボード

### TC-DASH-01 今月合計とペース予想表示
- **前提**: 当月 (2026-05) に支出が 1 件以上ある
- **手順**: `/dashboard` に navigate
- **期待**:
  - 「今月の合計」が当月の expense_records.total_amount 合計と一致
  - 「経過日数」が今日の日付に応じる（例: 5/10 → 10 日 / 31 日）
  - 「月末ペース予想」 = 合計 / 経過日数 × 31 が表示される

### TC-DASH-02 カテゴリ別円グラフ
- **前提**: 異なるカテゴリの支出が 2 件以上
- **手順**: `/dashboard` 表示
- **期待**: 円グラフが描画され、下に各カテゴリの金額が金額順で並ぶ

### TC-DASH-03 当月支出ゼロ時の表示
- **前提**: 当月の支出を全削除
- **手順**: `/dashboard` 表示
- **期待**: 円グラフ部分に「今月の支出がまだありません」表示、合計 ¥0

### TC-DASH-04 ⚠ 未計上固定費アラート + 一括計上
- **前提**: 固定費テンプレが 1 件以上、`last_generated_month` が前月以前または null
- **手順**:
  1. `/dashboard` 表示
  2. 「N 件を計上」ボタンが見えることを確認
  3. ボタンクリック
  4. **ユーザー操作**: ブラウザの alert を accept
- **期待**:
  - 「固定費 N 件を計上しました」alert
  - リフレッシュ後アラートが消えるか件数が減る
  - `/expense` で source_type=「固定費」の記録が増えている

## 17. 検出バグまとめ（重要度順）

### 🔴 Critical
- **B-DASH-04**: `web/lib/expense/recurring-actions.ts` で `"use server"` ファイルから object (`initialGeneratePendingState`) を export しているため、Server Action 読込時に Next.js が 500 を返し、**固定費自動計上機能（generatePendingExpensesAction）が一切動作しない**。`export const initialGeneratePendingState` を削除し定数を内部に閉じ込めるか、別ファイルへ分離する必要あり。

### 🟠 High
- **B-EDIT-01**: 編集モードで `record.purchased_at` (timestamptz, ISO 8601) を `<input type="date">` の `value` に直接渡すため、ブラウザは無効値として扱い空表示 → HTML5 required で submit 阻止。ユーザーは原因が分からないため操作不能に陥る。`record.purchased_at.slice(0, 10)` で YYYY-MM-DD に切り詰めて渡す対処が必要。
- **B-EDIT-02**: 編集時に `record.total_amount` (既存値、例: 500) が initial として `totalAmount` state に設定され、明細追加 / 編集後も「未入力なら明細から自動」が発動しない。結果として ヘッダの合計と DB の `expense_records.total_amount` が明細合計と乖離する。`updateExpenseRecord` で常に明細から再計算する、または編集 UI で「合計を自動計算」モードを追加する。

### 🟡 Medium
- **B-PROF-03**: 生年 input で `min=1900` を超えた値を入力 → HTML5 で submit 阻止されるが、**エラーメッセージが画面に表示されない**ため「保存ボタンを押しても何も起きない」UX。ユーザーが気付きにくい。
- **B-INPUT-MAN-04**: 値引 > 金額の組み合わせで合計が負になる場合、DB CHECK で阻止されるが「保存に失敗しました（汎用）」しか表示されない。事前にクライアント側でバリデーションする、または DB エラーの内容を判別して具体的なメッセージを返す。
- **B-REPORT-02**: `/reports` の「6ヶ月」「12ヶ月」切替リンクをクリックしても URL が変わらず描画も切り替わらない。前月リンクは動く。`typedRoutes` の object href Link 挙動差の可能性。

### 🟢 Low
- **B-CSV-01**: CSV の「日付」列が ISO 8601 timestamptz そのまま (`2026-05-10T00:00:00+00:00`)。Excel 表示で見にくい。`formatDate` ヘルパーで `YYYY-MM-DD` または日本語形式に整形して出力。

### ⏸ 環境依存（解消済み）
- ~~**TC-INPUT-OCR-01/02**~~: 2026-05-10 追試で Edge Function デプロイ完了後に ✅ 確認済み。

## 18. テスト中に発見した補助知見（メモリ化推奨）

- **Claude in Chrome の `form_input` ツールは React の `onChange` を発火させない**ため、controlled component の state は更新されない。`computer.left_click` (チェックボックス・select) や `computer.type` (テキスト入力) を使うと React onChange が動く。
- **JavaScript `dispatchEvent('change')` は React onChange を発火させる**ため、ファイル入力 (`input.files = dt.files`) は javascript_tool で代替可能（Chrome 拡張の file_upload は `<input class="hidden">` に対して `Not allowed` を返すケースあり）。
- **`pnpm build` 後に `pnpm dev` の起動中サーバーがあると `.next` キャッシュ衝突で 500**。`rm -rf .next` してから `pnpm dev` で復旧。
